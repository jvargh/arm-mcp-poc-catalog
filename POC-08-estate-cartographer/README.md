# Multi-subscription Estate Cartographer (ARM MCP PoC - POC-8)

A Copilot CLI / VS Code chat agent that generates a **hierarchical Mermaid/Markdown map**  
of an Azure estate (subscriptions → resource groups → resources → relationships) with a  
**high-risk overlay** (public IPs, unencrypted disks), and emits a byte-near-identical  
diagram every time it is run with the same scope and ruleset.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1.  Discovers all subscriptions in scope via `ResourceContainers` (R001).
2.  Enumerates resource groups per subscription (R002).
3.  Enumerates all resources with type, location, and tags (R003) - with `$skipToken` paging.
4.  Resolves NSG ↔ Subnet relationships (R004).
5.  Resolves Managed Identity → Key Vault relationships (R005).
6.  Overlays high-risk resources: public IPs with assigned addresses (R006).
7.  Overlays high-risk resources: unencrypted managed disks (R007).
8.  Renders a deterministic `flowchart TD` Mermaid diagram and markdown report.

## Why the output is deterministic

*   Queries are NOT generated by the LLM at run time - they are read verbatim from YAML.
*   Mermaid node IDs are derived from `sha256(resourceId_lower)[:8]` - never random.
*   Sort orders are pinned: subscriptions alphabetically, RGs alphabetically within sub,  
    resources by type then name.
*   Run ID is `MAP-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` - identical inputs → identical ID.

## Determinism Deviation

This PoC does not include `validate_query` in its tool allowlist per source spec.  
KQL correctness is assured by pre-testing during development. Operators running this PoC  
live should hand-verify rules.yaml KQL via the `validate_query` tool in another workspace  
if uncertain.

The SKILL.md procedure goes directly from scope-filter injection (`generate_query` context)  
→ `execute_query`. The `validate_query` step present in some other PoCs is intentionally  
absent here, in compliance with ratification #7 from  
`.squad/decisions/inbox/copilot-bishop-ratifications-2026-05-12.md`.

## How it works (end-to-end flow)

What happens after you type `@estate-cartographer map for scope prod`:

1.  **Chat client routes the message.** VS Code Copilot Chat sees the `@estate-cartographer`  
    mention, loads `.github/copilot/agents/estate-cartographer.agent.md` as the system prompt,  
    and reads its `tools:` declarations (`generate_query`, `execute_query`).
2.  **Workspace MCP server starts.** The runtime reads `.vscode/mcp.json`, starts the ARM MCP  
    server at `https://mcp.management.azure.com`, and performs the `initialize` handshake.
3.  **Step 1 - Load configuration.** The skill reads `runbooks/prod.yaml` + `prod.values.yaml`,  
    substitutes `${key}` tokens, and extracts `management_group`, `subscriptions[]`,  
    `max_subscriptions`, and `mermaid_max_nodes`.
4.  **Compute** `**run_id**`**.** Pure string assembly - no model judgement.
5.  **Step 2 - Evaluate every rule.** For each of R001–R007, the skill injects the scope filter  
    via string substitution into the literal KQL, then calls `execute_query`. Paging: if the  
    response includes a `$skipToken`, loop until exhausted or `max_subscriptions * 1000` rows.
6.  **Step 3 - Build estate model.** Sort subscriptions, RGs, resources, and derive Mermaid node  
    IDs deterministically. Annotate high-risk resources.
7.  **Step 4 - Render output.** Substitute `{{placeholder}}` tokens in `templates/output-report.md`  
    and write `exports/map-prod-latest.md`.
8.  **Result streamed back to chat.** Inline Mermaid renders in VS Code Preview.

## Install

1.  Clone this folder anywhere and open it as a workspace in VS Code.  
    The ARM MCP server is already declared at workspace scope in `.vscode/mcp.json` -  
    VS Code will prompt you to start it the first time you open chat.
    *   If your account isn't authorized for the ARM MCP preview, visit \<https://aka.ms/JoinARMMCP\>.
    *   For GitHub Copilot CLI: copy the `Azure Resource Manager MCP Server` entry from  
        `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2.  Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

> The MCP server entry (`.vscode/mcp.json`):
> 
> ```
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope (do this before first run)

`scope prod` maps to `runbooks/prod.yaml`. To keep secrets out of git, config is split:

| File | Committed? | Contains |
| --- | --- | --- |
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription IDs, MG ID, paging limits. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference - copy this to start. |

### Runbook keys

| Key | Required | Default | Description |
| --- | --- | --- | --- |
| `management_group` | No | `""` | MG ID; if set, subscriptions are discovered dynamically. |
| `subscriptions` | No\* | `[]` | Explicit sub GUIDs. Ignored if `management_group` is set. |
| `max_subscriptions` | No | `10` | Paging safety cap - max subs processed per run. |
| `mermaid_max_nodes` | No | `200` | Node cap for the Mermaid diagram. |

\* Either `management_group` or at least one entry in `subscriptions` is required.

## Run

VS Code chat:

```
@estate-cartographer map for scope prod
```

GitHub Copilot CLI:

```
gh copilot -p "Map the Azure estate for scope prod"
```

Drilldown on a specific resource:

```
@estate-cartographer drilldown /subscriptions/<sub-id>/resourceGroups/<rg>/providers/...
```

## Acceptance criteria mapping

| Criterion | Where it lives |
| --- | --- |
| Handles ≥10 subscriptions in one run with paging | `SKILL.md` Step 2 paging loop + `max_subscriptions` runbook key |
| Mermaid output renderable in VS Code | `templates/output-report.md` fenced `mermaid` block |
| High-risk overlay (public IPs, unencrypted disks) | R006 + R007 in `rules/rules.yaml` + `:::highRisk` Mermaid class |
