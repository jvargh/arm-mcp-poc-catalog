# Auto-Rollback Orchestrator (ARM MCP PoC — SRE-PoC-4)

A Copilot CLI / VS Code chat agent that watches an Azure Resource Manager deployment,
evaluates a fixed health gate after the deployment settles, and — on breach or failure —
**cancels** the deployment and re-deploys the **last-known-good template** automatically.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads runbook config (`runbooks/prod.yaml`) — subscription, resource group, deployment
   name, LKG template ref, and gate parameters.
2. Polls `get_arm_template_deployment_status` until the deployment reaches a terminal state
   or `health_gate_timeout_seconds` elapses.
3. Runs the fixed health gate (`rules/rules.yaml`) in **rule_id order** via `execute_query`.
4. On PASS → emits `SUCCEEDED` report and stops.
5. On FAIL or timeout → requests user confirmation, then calls `cancel_arm_template_deployment`,
   fetches the LKG template from `last_good_template_ref`, and re-deploys.
6. Rollback attempts are bounded by `max_rollback_attempts` (default 2). On exhaustion,
   emits `STATUS=HALTED` and stops.
7. Renders a canonical timeline (`[timestamp_utc] ACTION: description (status)`) and
   a structured report to `exports/rollback-<run_id>.md`.

## Why the output is deterministic

- Queries are NOT generated by the LLM — they are read verbatim from `rules.yaml`.
- Timeline format is pinned: `[timestamp_utc] ACTION: description (status)` — one line per step.
- Run ID is deterministic: `ROLL-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.
- Health gate evaluates rules in `rule_id` order (R001 → R002 → R003 → R004). No reordering.
- Rollback cap is an integer from the runbook (`max_rollback_attempts`). No LLM judgment.

## Determinism Deviation

> **This PoC does not include `validate_query` in its tool allowlist per source spec.**
> KQL correctness is assured by pre-testing during development. Operators running this PoC
> live should hand-verify `rules.yaml` KQL via the `validate_query` tool in another workspace
> if uncertain.
>
> **This PoC does not include `generate_query` in its tool allowlist.**
> All KQL is pre-defined as literal strings in `rules/rules.yaml`. The agent MUST read KQL
> verbatim from that file and MUST NOT derive, generate, or paraphrase queries at runtime.
> Both exclusions are enforced by agent hard rules and by the absence of the tools from the
> `tools:` block in `auto-rollback.agent.md`.

## How it works (end-to-end flow)

1. **Chat routes the message.** VS Code sees `@auto-rollback watch`, loads
   `.github/copilot/agents/auto-rollback.agent.md` as the system prompt.
2. **MCP server starts.** Runtime reads `.vscode/mcp.json`, connects to
   `https://mcp.management.azure.com`, handshakes, exposes 4 tools.
3. **Agent loads config.** Reads `runbooks/prod.yaml` + `prod.values.yaml` (substitution).
   Computes `run_id`.
4. **Agent polls deployment status.** Calls `get_arm_template_deployment_status` in a loop.
   Writes one timeline line per poll.
5. **Deployment settles.** On `Succeeded` → health gate. On `Failed`/`Canceled`/timeout →
   skip to cancel + rollback.
6. **Health gate.** For each rule R001→R004: call `execute_query` with literal KQL,
   record `PASS`/`FAIL`. On any FAIL → breach.
7. **Cancel flow.** User confirmation required. Calls `cancel_arm_template_deployment`.
   Writes audit log.
8. **Rollback.** Fetches LKG template. In v1: simulated (`[SIMULATED]`). Re-runs health
   gate. On second failure → `HALTED`.
9. **Output.** Renders report + timeline to chat and to `exports/rollback-<run_id>.md`.

## Install

1. Clone this folder and open it as a VS Code workspace. The ARM MCP server is declared
   in `.vscode/mcp.json` — VS Code will prompt to start it on first chat.
   - If not yet authorized: <https://aka.ms/JoinARMMCP>.
   - For GitHub Copilot CLI: copy the `Azure Resource Manager MCP Server` entry from
     `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with **Reader** + **Resource Graph Reader** on the target
   scope. For actual deploys you also need **Contributor** on the target RG.

> MCP server entry (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope

Copy and fill in the values file before first run:

```powershell
Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
```

Edit `runbooks/prod.values.yaml`:

```yaml
subscription_id: "11111111-2222-3333-4444-555555555555"
resource_group: "payments-prod-rg"
deployment_name: "payments-deploy-20260512"
template_file: "infra/main.json"
parameters_file: "infra/main.parameters.json"
last_good_template_ref: "git:refs/heads/main:infra/main.json"
last_good_parameters_file: "infra/lkg.parameters.json"
```

Verify `.gitignore` excludes `prod.values.yaml` (the root `.gitignore` contains
`**/runbooks/*.values.yaml`).

## Run

VS Code chat:

```
@auto-rollback watch deployment payments-deploy-20260512 scope prod
```

Manual rollback:

```
@auto-rollback rollback scope prod
```

Cancel in-progress deployment:

```
@auto-rollback cancel deployment payments-deploy-20260512 scope prod
```

## Acceptance criteria

| Criterion | Where it lives |
|---|---|
| Pulls last-good template from Git ref | `runbooks/prod.yaml` → `last_good_template_ref`; SKILL.md Step 6 |
| Configurable health gate (ARG) with timeout | `health_gate_timeout_seconds` in runbook; SKILL.md Steps 3–4 |
| Bounded rollback attempts | `max_rollback_attempts` in runbook; SKILL.md Step 6; agent hard rule #3 |
| Incident-ready timeline | `[timestamp_utc] ACTION: description (status)` in SKILL.md Steps 2–6 |
| Cancel path with per-deployment confirmation | SKILL.md Step 5; `prompts/cancel.prompt.md`; agent hard rule #4 |
| 4-tool allowlist (no derivation tools) | `auto-rollback.agent.md` tools block; agent hard rule #2 |

## Tool allowlist (exactly 4 tools)

| Tool | Purpose |
|---|---|
| `create_template_deployment` | Re-deploy LKG template (v1: simulated only) |
| `get_arm_template_deployment_status` | Poll deployment status during watch |
| `cancel_arm_template_deployment` | Cancel in-progress deployment |
| `execute_query` | Run literal health-gate KQL from rules.yaml |

`generate_query` and `validate_query` are **not** in the allowlist. See
[Determinism Deviation](#determinism-deviation).
