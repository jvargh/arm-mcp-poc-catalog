# POC-12 — ChatOps Bot (ARM MCP)

A Copilot CLI / VS Code chat agent that lets non-engineers self-serve common Azure resource
questions through a Teams or Slack bot interface — backed by the Azure Resource Manager MCP
Server, **fully read-only**, with an append-only audit trail.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Receives natural-language questions from Teams / Slack users (e.g. "how many storage accounts do we have?").
2. Maps each question to a **pre-canned ARG query category** from `skills/chatops-bot/rules/rules.yaml`.
3. Calls `generate_query` (for audit compliance) then `execute_query` (ARM MCP) with the **verbatim KQL** — no LLM query invention.
4. Renders a response using a **fixed markdown template** (`templates/output-report.md`).
5. Appends one JSON audit log line per query to `runbook.audit_log_path`.
6. Exposes an `audit` verb to display the full audit trail sorted by timestamp descending.

## Why the output is deterministic

* Queries are **NOT generated by the LLM** at run time — they are read verbatim from YAML.
* The skill instructs the agent to emit responses using fixed templates with no paraphrasing.
* Sort orders, column headers, and section order are all pinned in `SKILL.md`.
* Run ID is the scope + UTC date + rules hash — identical inputs → identical run ID.
* Allowed question categories are gated by `runbook.allowed_question_categories` — unknown categories are blocked, not guessed.

## Determinism Deviation

> **`validate_query` is not in this PoC's tool allowlist.**
>
> This PoC does not include `validate_query` in its tool allowlist per source spec. KQL correctness
> is assured by pre-testing during development. Operators running this PoC live should hand-verify
> `rules.yaml` KQL via the `validate_query` tool in another workspace if uncertain.
>
> The SKILL.md procedure goes directly from `generate_query` → `execute_query`, skipping the
> validate step. This is binding per Bishop ratification #7 (2026-05-12).

## Acceptance criteria

| Criterion | Where it lives |
|---|---|
| RBAC pass-through via on-behalf-of token | ARM MCP handles auth via `az login` identity — see [RBAC pass-through](#rbac-pass-through) below |
| Read-only mode toggle that disables `create_template_deployment` / `cancel_*` | `read_only_mode: true` in `runbooks/prod.yaml` + tool allowlist in `chatops-bot.agent.md` (only `generate_query`, `execute_query`) |
| Audit log of every question + ARG query produced | `runbook.audit_log_path` (append-only JSON lines); format: `{timestamp_utc, user, question, kql_generated, row_count, run_id}` |

## RBAC pass-through

Authentication is conceptual in this PoC — the ARM MCP server handles it transparently:

1. The operator runs `az login` (or uses a managed identity in CI).
2. VS Code / Copilot CLI brokers the signed-in token to the ARM MCP server at `https://mcp.management.azure.com`.
3. Every `execute_query` call carries the user's identity — ARG enforces subscription-level RBAC.
4. **This agent never handles credentials directly.** Minimum required role: `Reader` + `Resource Graph Reader` on each listed subscription.

No additional configuration is needed beyond `az login` and correct RBAC assignment.

## How it works (end-to-end flow)

1. **User types a question** in Teams or Slack (bot integration is external to this PoC; the agent handles the question text).
2. **`@chatops-bot ask`** routes to `prompts/ask.prompt.md`, loads the agent system prompt from `agents/chatops-bot.agent.md`.
3. **Skill step 1** loads `runbooks/prod.yaml` (substituting from `prod.values.yaml`) and `rules/rules.yaml`.
4. **Skill step 2** keyword-matches the question to a rule `id`; checks `allowed_question_categories`.
5. **Skill step 3** calls `generate_query` (output discarded) then `execute_query` with the **verbatim KQL** from rules.yaml.
6. **Skill step 4** writes one JSON audit line to `audit_log_path`.
7. **Skill step 5** renders `templates/output-report.md` via literal `{{placeholder}}` substitution.
8. **`@chatops-bot audit`** reads `audit_log_path`, sorts descending by timestamp, renders `templates/output-audit.md`.

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is already declared in [`.vscode/mcp.json`](.vscode/mcp.json).
2. Sign in to Azure: `az login`.
3. Copy the values example and fill in your subscription ID:
   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```
4. Edit `runbooks/prod.values.yaml` with your subscription GUID, audit log path, and allowed categories.

## Configure your scope

`scope prod` maps to `runbooks/prod.yaml`. Two-file pattern (template + values) mirrors the reference implementation:

| File | Committed? | Contains |
|---|---|---|
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens |
| `runbooks/prod.values.yaml` | ❌ gitignored | Real subscription ID, audit log path |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference |

## Run

VS Code chat:
```
@chatops-bot ask how many storage accounts do we have?
@chatops-bot ask what's our VM count by region?
@chatops-bot audit
```

GitHub Copilot CLI:
```
copilot -p "Use the chatops-bot agent to ask how many SQL databases are in eastus2"
```

> **CLI users:** see [Copilot CLI usage notes](../README.md#copilot-cli-usage-notes) — `gh copilot` has a quoting bug on Windows when `copilot` lives on a path with spaces, `@agent` mentions don't work in the CLI, and first runs take a few minutes.

```
POC-12-chatops-bot/
  README.md

  .github/copilot/
    agents/chatops-bot.agent.md       # agent persona + tool allowlist (generate_query, execute_query only)
    skills/chatops-bot/
      SKILL.md                        # deterministic procedure (no validate_query step)
      rules/rules.yaml                # 5 pre-canned query categories: id, kql, weight=0
      templates/
        output-report.md              # fixed ask-response format
        output-audit.md               # fixed audit-log display format
      prompts/
        ask.prompt.md                 # ask verb entry point
        audit.prompt.md               # audit verb entry point
  runbooks/
    prod.yaml                         # committed template (placeholders only)
    prod.values.yaml.example          # schema reference — copy and fill in real values
  exports/
    .gitkeep                          # audit.log and test-run.md land here
    test-run.md                       # simulated test session
```
