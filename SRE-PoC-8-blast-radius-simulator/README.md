# Blast-Radius Simulator for ARM Templates (ARM MCP SRE PoC 8)

An SRE-grade Copilot CLI / VS Code chat agent that parses an ARM template,
projects the change set against live ARG data, and **quantifies user-facing risk**
across DNS, endpoints, identities, and certificate chains — giving operators a
deterministic strategy recommendation before every deploy.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Reads a target ARM template path from the runbook (`template_path`).
2. Parses the template to extract resource types and names in the change set.
3. For each impact rule (R001–R005): `validate_query` → `execute_query` (ARM MCP).
4. Classifies findings into five user-facing impact categories.
5. Computes a `risk_score = sum(category_weight × affected_resource_count)`.
6. Renders a simulation report using a **fixed markdown template**.
7. Recommends a deployment strategy (canary / blue-green / staggered) based on
   score thresholds defined in the runbook.

## Why the output is deterministic

* Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
* The skill instructs the agent to render the report using a fixed template with no paraphrasing.
* Risk score formula is fixed: `risk_score = sum(category_weight × affected_resource_count)`.
* Sort order is pinned: descending by `category_risk`, ties broken by `rule_id` ascending.
* Strategy recommendation is a pure threshold lookup in `runbooks/prod.yaml`.
* Run ID is deterministic: `BLAST-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.

## How it works (end-to-end flow)

What happens after you type `@blast-radius-simulator simulate scope prod`:

1. **Chat client routes the message.** VS Code Copilot Chat loads
   `.github/copilot/agents/blast-radius-simulator.agent.md` as the system prompt
   and reads its `tools:` / `mcp:` declarations.
2. **Workspace MCP servers start.** The runtime reads `.vscode/mcp.json`, starts
   the `Azure Resource Manager MCP Server`, and obtains the tool list via `tools/list`.
3. **LLM reads inputs.** Reads `runbooks/prod.yaml` (scope, subscriptions,
   `template_path`, `risk_score_weights`, `deploy_strategy_recommendations`)
   and `rules/rules.yaml` (5 rules with literal KQL).
4. **LLM computes `run_id`** deterministically:
   `BLAST-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.
5. **LLM parses the target template** at `template_path`. Extracts resource types,
   names, and change scope.
6. **LLM runs the rule loop (R001–R005).** For each rule:
   `validate_query` → `execute_query` with literal KQL from `rules.yaml` and
   `subscriptions` from the runbook.
7. **Impact classification.** Findings grouped by category (dns_endpoint,
   identity_rotation, cert_regen, rbac, dependency_edge).
   R004 emits `STATUS=SKIPPED` if `authorizationresources` table is unavailable.
8. **Risk score.** `risk_score = sum(category_weight × affected_resource_count)`
   using weights from `risk_score_weights` in the runbook. Integer.
9. **Strategy recommendation.** Pure threshold lookup in
   `deploy_strategy_recommendations` (canary / blue-green / staggered).
10. **Render output.** Literal substitution into `templates/output-report.md`.
    Written to `exports/blast-radius-<scope>-latest.md`.
11. **No deploy.** `create_template_deployment` is in the tool allowlist for
    future native what-if integration but **MUST NOT be called in v1**.

## Known limitations

* **v1 renders locally — no actual what-if API call.** `create_template_deployment`
  is present in the tool allowlist for future native what-if integration but is
  **intentionally not called in v1**. Per ratification #3, the hard rule in `agent.md`
  forbids invoking it in `simulate` mode. The report is derived from ARG queries
  against the parsed template.
* `authorizationresources` table (R004) may not be available in all subscriptions.
  The rule emits `STATUS=SKIPPED REASON=authorizationresources-unavailable` and
  continues — per ratification #2.
* `get_arm_template_deployment_status` is intentionally absent from the tool
  allowlist. Do not add it.

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is already declared at workspace scope in `.vscode/mcp.json`.
   * If your VS Code account is not yet authorized for the ARM MCP preview,
     visit <https://aka.ms/JoinARMMCP>.
   * For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server`
     entry from `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

> The MCP server entry at workspace scope (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope

`scope prod` maps to `runbooks/prod.yaml`. To keep secrets out of git, scope config
is split into two files:

| File | Committed? | Contains |
| --- | --- | --- |
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Real sub ID and template path. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference — copy this to start. |

### First-time setup

1. **Copy the example to a real values file:**

   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```

2. **Edit `runbooks/prod.values.yaml`** and fill in real values:

   ```yaml
   subscription_id: "11111111-2222-3333-4444-555555555555"
   template_path: "templates/my-app-template.json"
   ```

3. **Verify `.gitignore` excludes it** (root `.gitignore` has
   `**/runbooks/*.values.yaml`). Run `git status` and confirm `prod.values.yaml`
   is NOT listed.

### Adjusting risk weights and strategy thresholds

Risk weights and strategy thresholds live in `runbooks/prod.yaml` and can be
tuned per environment without touching any code:

```yaml
risk_score_weights:
  dns_endpoint:      15   # highest — DNS outages are user-visible immediately
  cert_regen:        12
  identity_rotation: 10
  rbac:               9
  dependency_edge:    8

deploy_strategy_recommendations:
  low_threshold: 20    # score < 20  → canary
  medium_threshold: 60 # score < 60  → blue-green
  strategies:          # score >= 60 → staggered
    low:    canary
    medium: blue-green
    high:   staggered
```


## Acceptance criteria mapping

| Criterion | Where it lives |
| --- | --- |
| Maps changes to user-impact categories | R001–R005 in `rules/rules.yaml`; Step 4 in `SKILL.md` |
| Surfaces dependency edges | R005 query + `{{dependency_edges_block}}` in `output-report.md` |
| Risk score + recommended strategy | `risk_score_weights` + `deploy_strategy_recommendations` in `runbooks/prod.yaml`; Step 5 in `SKILL.md` |
