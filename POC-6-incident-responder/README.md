# Incident Responder (ARM MCP PoC — POC-6)

During incidents, answers blast-radius questions by querying ARG `resourcechanges` +
in-flight deployments, with cancel capability.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed rule pack (`skills/incident-responder/rules/rules.yaml`) — 3 ARG rules
   with **pre-canned KQL queries**.
2. For every rule: `generate_query` → `execute_query` (ARM MCP). No `validate_query` step
   (see [Determinism Deviation](#determinism-deviation)).
3. For each in-flight deployment found: `get_arm_template_deployment_status` to enrich status.
4. Renders a triage report using a **fixed markdown template** (`templates/output-report.md`).
5. Supports a `cancel` verb to stop a running deployment after **explicit user confirmation**.
6. Appends an audit JSON-line to `exports/incident-audit.jsonl` for every triage and cancel action.

## Why the output is deterministic

* Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
* The skill instructs the agent to emit the report using a fixed template with no paraphrasing.
* Sort orders, column headers, and section order are all pinned in `SKILL.md`.
* Run ID is `INC-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` — identical inputs → identical run ID.
* The only runtime substitution is the scope (subscriptions, RG list) and the
  `${time_window_hours}` token from the runbook.

## Determinism Deviation

> **This PoC does not include `validate_query` in its tool allowlist per source spec.**
>
> Per ratification #7 (`.squad/decisions/inbox/copilot-bishop-ratifications-2026-05-12.md`),
> `validate_query` is NOT in the tool allowlist for POC-6. The skill procedure goes directly
> `generate_query` → `execute_query`, skipping the validate step.
>
> KQL correctness is assured by pre-testing during development. Operators running this PoC
> live should hand-verify `rules.yaml` KQL via the `validate_query` tool in another workspace
> if uncertain.

## Read-only posture

POC-6 is **READ-ONLY** with one exception: `cancel_arm_template_deployment` is available
but requires explicit per-deployment user confirmation before it is invoked. The agent
never calls `create_template_deployment`.

## How it works (end-to-end flow)

1. **Chat client routes the message.** VS Code Copilot Chat sees the `@incident-responder`
   mention, loads `.github/copilot/agents/incident-responder.agent.md` as the system prompt.
2. **Workspace MCP server starts.** The runtime reads `.vscode/mcp.json`, connects to
   `https://mcp.management.azure.com`, and discovers the tool descriptors.
3. **LLM follows SKILL.md step 1 — load inputs.** Reads `runbooks/prod.yaml` (scope,
   subscriptions, RG lists, `default_time_window_hours`) and `rules/rules.yaml`
   (3 rule definitions with literal KQL). Substitutes `${time_window_hours}` in KQL.
4. **LLM computes `run_id` deterministically.**
   `INC-{YYYYMMDD}-prod-{sha256(rules.yaml)[:8]}` — plain string assembly.
5. **LLM enters the per-rule loop (SKILL.md step 2).** For each rule it calls
   `generate_query` with the literal KQL + scope, then `execute_query`. No `validate_query`.
6. **R001 / R003 skip handling.** If `resourcechanges` or `authorizationresources` tables
   are unavailable (table-not-found error or empty result), the rule is marked
   `STATUS=SKIPPED` and the run continues with the next rule.
7. **LLM enriches deployments (SKILL.md step 3).** Calls `get_arm_template_deployment_status`
   for each deployment returned by R002.
8. **LLM renders the triage report (SKILL.md step 4).** Literal `{{placeholder}}`
   substitution into `templates/output-report.md`. Layout is frozen.
9. **Audit line appended.** One JSON-line written to `exports/incident-audit.jsonl`.
10. **Cancel verb (SKILL.md step 5).** User invokes `@incident-responder cancel deployment <id>`.
    Agent checks status, presents a mandatory confirmation block, waits for "yes" or "y",
    then calls `cancel_arm_template_deployment`. Audit line written regardless of outcome.

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is declared at workspace scope in `.vscode/mcp.json`.
   * If your VS Code account isn't yet authorized: <https://aka.ms/JoinARMMCP>.
   * For GitHub Copilot CLI: copy the `Azure Resource Manager MCP Server` entry from
     `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with **Reader + Resource Graph Reader** on the target scope.

> MCP server entry (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope

Copy the example values file and fill in your real subscription and RG names:

```powershell
Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
```

Edit `runbooks/prod.values.yaml`:

```yaml
subscription_id: "11111111-2222-3333-4444-555555555555"

rg_include:
  - "payments-prod-rg"
  - "checkout-prod-rg"

rg_exclude: []

incident_scopes:
  - "payments"
```

`prod.values.yaml` is gitignored. The committed `prod.yaml` is a template with `${key}` tokens only.

## Run

VS Code chat:

```
@incident-responder triage scope prod
```

GitHub Copilot CLI:

```
gh copilot -p "Run incident responder triage for scope prod"
```

Cancel a running deployment:

```
@incident-responder cancel deployment /subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.Resources/deployments/<name> scope prod
```

## Acceptance criteria mapping

| Criterion | Where it lives |
|---|---|
| Time-windowed change feed | R001 KQL in `rules.yaml`; `${time_window_hours}` from runbook |
| In-flight deployment list with cancel action | R002 KQL + `get_arm_template_deployment_status`; `cancel` verb in SKILL.md step 5 |
| Audit log | `exports/incident-audit.jsonl` — one line per triage, one per cancel |
| Cancel requires explicit confirmation | SKILL.md step 5c + `cancel.prompt.md` strict requirement |
| resourcechanges / authorizationresources resilience | `skip_if_unavailable: true` on R001 + R003; ratifications #1 + #2 |
| Read-only posture | No `create_template_deployment`; confirmed in agent.md hard rule 7 |
