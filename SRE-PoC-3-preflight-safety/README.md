# Pre-flight Deployment Safety Check (SRE-PoC-3)

A Copilot CLI / VS Code chat agent that runs a configurable battery of ARG
health-precondition queries before every prod ARM deployment, refusing to deploy
until all checks pass.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed rule pack (`skills/preflight-safety/rules/rules.yaml`) — 9 preflight
   checks with **pre-canned ARG queries**.
2. For every rule: `validate_query` → `execute_query` (ARM MCP). Rules run in
   **rule_id ascending order** (R001 first) within a configurable timeout budget.
3. Evaluates each check: **0 rows = PASS**, **≥1 rows = FAIL**, table-unavailable = **SKIP**.
4. Renders a deterministic preflight-results report via a fixed markdown template.
5. **Gates the deployment**: refuses to deploy if any check FAILs, unless
   `force_deploy_flag` is set (audit warning emitted).
6. In v1: renders a "Would deploy (NOT EXECUTED)" outcome — does not call
   `create_template_deployment`.

## Why the output is deterministic

* Queries are NOT generated by the LLM at run time — read verbatim from YAML.
* The skill instructs the agent to emit the report using a fixed template.
* Check order is pinned: rule_id ascending (R001, R002 … R009).
* PASS/FAIL/SKIP logic is deterministic: zero rows = PASS, non-zero = FAIL.
* Run ID format: `PRE-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` — pure string assembly.
* Time budget enforced: all checks ≤ `preflight_timeout_seconds` (default 30).

## Determinism Deviation

This PoC **includes** `validate_query` in its tool allowlist per source spec.
The `validate_query` → `execute_query` pattern is used on the hot path.

## How it works (end-to-end flow)

1. **Chat client routes the message.** VS Code sees `@preflight-safety`, loads
   `.github/copilot/agents/preflight-safety.agent.md` as the system prompt.
2. **MCP server starts** from `.vscode/mcp.json`. The ARM MCP server descriptor
   lists the 5 tools in the allowlist.
3. **LLM reads runbook** (`runbooks/prod.yaml` + values file), extracts `subscriptions`,
   `rg_include`, `rg_exclude`, `preflight_rules_per_env`, `force_deploy_flag`,
   `preflight_timeout_seconds`, `quota_limits`.
4. **LLM computes `run_id`** deterministically: `PRE-{YYYYMMDD}-{scope}-{hash8}`.
5. **LLM enters the per-rule loop** in rule_id order. For each rule it calls
   `validate_query` then `execute_query` with the literal KQL from `rules.yaml`.
6. **SKIP handling:** if `skip_if_unavailable: true` AND the query errors with
   table-not-found or returns no data — the check is SKIPPED (non-fatal). Affected
   rules: R001, R004, R005, R009.
7. **Decision:** `checks_fail == 0` → PASS. Any FAIL + `force_deploy_flag=false` → BLOCK.
   Any FAIL + `force_deploy_flag=true` → FORCE+AUDIT.
8. **v1 deploy path:** LLM renders the "Would deploy (NOT EXECUTED in v1)" section.
   `create_template_deployment` is **never called**.
9. **Report rendered** via `templates/output-preflight-results.md` (preflight verb) or
   `templates/output-report.md` (deploy verb).

## Install

1. Clone this folder and open it as a workspace in VS Code.
   `.vscode/mcp.json` declares the ARM MCP server — VS Code will prompt to start it.
   * If not yet authorized: <https://aka.ms/JoinARMMCP>
   * GitHub Copilot CLI: copy the server entry into `~/.copilot/mcp.json`.
2. Sign in (`az login`) with **Reader + Resource Graph Reader** on the target scope.

> MCP config at workspace scope (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope

`scope prod` maps to `runbooks/prod.yaml`. Two-file pattern — same as the reference
implementation:

| File | Committed? | Contains |
|---|---|---|
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID, RG names, quota limits. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference — copy this to start. |

### First-time setup

```powershell
Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
# Edit prod.values.yaml with real values
```

Important keys in `prod.values.yaml`:

```yaml
subscription_id: "11111111-2222-3333-4444-555555555555"
rg_include: ["payments-prod-rg"]
rg_exclude: []
deployment_target_rg: "payments-prod-rg"

# Quota limits for R005 (keep in sync with az vm list-usage):
quota_limits:
  vm_cores_per_region: 100
  public_ip_addresses: 50
  network_interfaces: 200
  storage_accounts: 250
```

Set all quota limits to `0` to SKIP R005 quota checks.

## Runbook keys reference

| Key | Type | Default | Description |
|---|---|---|---|
| `subscriptions` | list | required | Azure subscription GUIDs to query |
| `rg_include` | list | `[]` | RG name substrings to include (case-insensitive) |
| `rg_exclude` | list | `[]` | RG name substrings to exclude |
| `deployment_target_rg` | string | required | RG where the ARM template deploys |
| `preflight_rules_per_env` | map | all rules | Per-env rule_id filter |
| `force_deploy_flag` | bool | `false` | Override FAIL and deploy with audit warning |
| `preflight_timeout_seconds` | int | `30` | Total timeout for all checks |
| `quota_limits` | map | all 0 | Known quota limits for R005 |

## Run

VS Code chat:

```
@preflight-safety preflight scope prod
```

GitHub Copilot CLI:

```
gh copilot -p "Run preflight safety check for scope prod"
```

Deploy (after PASS):

```
@preflight-safety deploy scope prod template templates/my-template.json params templates/my-template.parameters.json
```

Check deployment status:

```
@preflight-safety status
```

## Preflight Rules

| Rule ID | Title | Severity | Skip if unavailable |
|---|---|---|---|
| R001 | Active resource health incidents in scope | critical | ✅ yes |
| R002 | Overlapping deployments already Running | high | no |
| R003 | Dependency resources not in Succeeded state | high | no |
| R004 | Recent throttling/errors (resourcechanges, 15min) | high | ✅ yes |
| R005 | Quota headroom | medium | ✅ yes |
| R006 | Resources lacking `iac-managed` tag (drift) | medium | no |
| R007 | Resources missing required deployment tags | medium | no |
| R008 | Failed deployments in the last 1 hour | high | no |
| R009 | Region capacity signal | low | ✅ yes |

SKIP rules (R001, R004, R005, R009) carry `skip_if_unavailable: true` per
ratification #1 (R004: `resourcechanges` table may not be enabled), ratification #2 (R001:
`HealthResources` may not be queryable), and Bishop's notes (R005/R009: ARG cannot
determine quota limits or region capacity ceilings).

## Acceptance criteria mapping

| Criterion | Where it lives |
|---|---|
| Configurable preflight ruleset per env | `runbooks/prod.yaml` → `preflight_rules_per_env` |
| Each check has pass/fail + remediation hint | `rules/rules.yaml` → `remediation_hint` per rule |
| Force-deploy emits audit warning | `agent.md` hard rule 8 + `SKILL.md` Step 3 + `deploy.prompt.md` |
| Preflight runs <30s | `preflight_timeout_seconds: 30` in runbook + SKILL.md Step 2 budget check |

## What-if only (locked decision + ratification #3)

v1 does **not** invoke `create_template_deployment`. The `deploy` verb renders a
"Would deploy (NOT EXECUTED in v1)" appendix showing the template and parameters that
**would** be submitted. This honors the locked decision: *what-if templates only — never
call `create_template_deployment` in any test path.*

See `exports/test-run.md` for a simulated outcome showing PASS+would-deploy and
FAIL+block flows.
