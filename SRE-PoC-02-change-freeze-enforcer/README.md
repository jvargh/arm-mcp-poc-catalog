# Change-Freeze Enforcer (SRE-PoC-2 — ARM MCP PoC)

A Copilot CLI / VS Code chat agent that intercepts ARM deployment calls during declared
freeze windows, either **blocking** them or requiring break-glass justification with a
permanent audit log entry.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads the freeze schedule from `runbooks/prod.yaml` — a list of `freeze_windows`
   (start/end UTC timestamps, scopes, severity) and `break_glass_required_fields`.
2. For every rule in `skills/change-freeze-enforcer/rules/rules.yaml`:
   `validate_query` → `execute_query` (ARM MCP) using **pre-defined literal KQL**.
3. Resolves the deployment's target scope (R001), checks whether a freeze window is
   currently active (R002, time-based), checks scope overlap (R003), and checks for an
   exemption tag (R004).
4. Emits a **binary decision**: `PASS`, `BLOCK`, or `OVERRIDE_ALLOW`.
5. On **PASS**: renders a would-deploy report (`output-report.md`) and writes it to `exports/`.
6. On **BLOCK**: renders `output-blocked.md` explaining the freeze and how to override.
7. On **OVERRIDE_ALLOW**: renders `output-override.md`, appends a JSON audit line to
   `exports/override-audit.log`, and writes the report to `exports/`.

The agent **does not deploy its own remediation templates**. Its role is to gate the
operator's deployment — not to deploy anything itself.

## Why the output is deterministic

- Queries are **not** generated by the LLM at run time — they are read verbatim from
  `rules/rules.yaml`.
- The freeze-window comparison is pure arithmetic: `current_utc >= start_utc AND current_utc < end_utc`.
- The block decision is binary: exactly one of `PASS`, `BLOCK`, `OVERRIDE_ALLOW` — no
  partial states, no fuzzy judgement.
- Run ID format is `FREEZE-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` — plain string
  assembly, identical inputs → identical run ID.
- Override audit log format is fixed: `{timestamp_utc, principal, cr_id, justification, scope, template_name}`.

## How it works (end-to-end flow)

What happens after you type `@change-freeze-enforcer deploy template: my-app.json target_scope: prod-rg scope: prod`.

1. **Chat client routes the message.** VS Code Copilot Chat sees the `@change-freeze-enforcer`
   mention, loads `.github/copilot/agents/change-freeze-enforcer.agent.md` as the system
   prompt, and reads its `tools:` declarations.
2. **Workspace MCP server starts.** The runtime reads `.vscode/mcp.json`, sees the
   `Azure Resource Manager MCP Server` entry, performs the MCP `initialize` handshake.
   The server returns tool descriptors including `validate_query`, `execute_query`,
   `create_template_deployment`, `get_arm_template_deployment_status`.
3. **LLM gets its toolbox + hard rules.** The model sees the agent's hard rules, SKILL.md
   procedure, the user prompt, and MCP tool schemas. No Azure call has happened yet.
4. **LLM follows skill step 1 — load configuration.** Reads `runbooks/prod.yaml` (with
   values substituted from `prod.values.yaml`), extracts `freeze_windows`,
   `break_glass_required_fields`, `exempt_tags`, and `subscriptions`.
5. **LLM computes `run_id` deterministically.** `FREEZE-{YYYYMMDD}-prod-{sha256(rules.yaml)[:8]}`.
6. **LLM enters the per-rule loop (skill step 2).** For each rule, takes the literal KQL
   from `rules.yaml` and calls `validate_query` with it.
7. **`validate_query` round-trip.** ARM MCP validates KQL syntax/auth and returns valid or
   error. On error, rule is marked `INVALID` and skipped.
8. **`execute_query` round-trip.** ARM MCP runs KQL against ARG using your signed-in Azure
   identity. Rows come back as JSON.
9. **All 4 rules evaluated.** R001 rows confirm scope. R002 rows provide lock evidence.
   R003 rows list resource groups for overlap check. R004 rows identify exempt resources.
10. **Freeze check (skill step 3).** Time comparison against `freeze_windows` in memory.
    Scope overlap check against R003 rows. Exemption check against R004 rows.
11. **Decision computed (skill step 5).** Binary: PASS / BLOCK / OVERRIDE_ALLOW.
12. **Output rendered (skill step 6).** Fixed template substitution. No paraphrasing.
13. **Export written.** Report file and (on override) audit log line appended.
14. **Result returned to chat.** The rendered markdown decision report.

**Where the LLM is a workflow runner:** steps 1, 4, 5, 6, 10, 11, 12, 13.  
**Where MCP does the heavy lifting:** steps 7–9 — validating and running literal KQL.

## Install

1. Clone this folder and open it as a workspace in VS Code.  
   The ARM MCP server is **already declared** in [`.vscode/mcp.json`](.vscode/mcp.json) — VS
   Code will prompt you to start it.
   - If not yet authorized for the ARM MCP preview: <https://aka.ms/JoinARMMCP>.
   - For Copilot CLI users: copy the server entry from `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope

### Two-file pattern

| File | Committed? | Contains |
|---|---|---|
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real sub ID and freeze windows. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference — copy this to start. |

### First-time setup

```powershell
Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
```

Edit `runbooks/prod.values.yaml` and fill in:
- `subscription_id` — your Azure subscription GUID
- `freeze_window_1_start` / `freeze_window_1_end` — ISO 8601 UTC timestamps
- `freeze_window_1_scopes` — list of resource group name patterns to freeze
- `freeze_window_1_severity` — `critical`, `high`, `medium`, or `low`

Verify `.gitignore` excludes it (root `.gitignore` has `**/runbooks/*.values.yaml`). Run
`git status` and confirm `prod.values.yaml` is not listed.

### Adding more freeze windows

Add a second entry to `freeze_windows` in `prod.yaml` and the corresponding `_2` keys in
`prod.values.yaml`. Each freeze window is independent.

## Run

VS Code chat:

```
@change-freeze-enforcer deploy template: my-app.json target_scope: payments-prod-rg
```

Override (break-glass):

```
@change-freeze-enforcer override template: my-app.json target_scope: payments-prod-rg cr_id: CHG0012345 justification: P1 incident rollback
```

Freeze schedule status:

```
@change-freeze-enforcer status scope: prod
```

Check status of an existing deployment:

```
@change-freeze-enforcer status deployment_name: my-app-deploy-20261222
```

| Criterion | Where it lives |
|---|---|
| Freeze schedule + scopes in YAML | `runbooks/prod.yaml` + `prod.values.yaml.example` |
| Resolves template's target scope | SKILL.md Step 3 (R001) + `rules.yaml` R001 KQL |

## Determinism Deviation

> **`generate_query` is NOT in the tool allowlist for this PoC** (per source manifest
> "Special concerns" and ratification #1).

This PoC does not include `generate_query` in its `tools:` block. All KQL is fully
pre-defined verbatim in `rules/rules.yaml` and is never derived at run time. The agent's
hard rule #1 explicitly forbids calling `generate_query`.

This deviation is intentional and by design. The freeze-window check is time-deterministic
(comparing `current_utc` against `freeze_windows` timestamps) and does not require dynamic
query construction. KQL correctness is assured by pre-testing during development.

Operators running this PoC live who wish to independently verify the KQL queries should
use the `validate_query` tool manually in another VS Code workspace against their subscription.

## Override Audit Trail

Every break-glass override appends a JSON line to `exports/override-audit.log`:

```json
{
  "timestamp_utc": "2026-12-22T15:00:00Z",
  "principal": "operator@contoso.com",
  "cr_id": "CHG0012345",
  "justification": "P1 incident rollback — payments pipeline down",
  "scope": "payments-prod-rg",
  "template_name": "payments-api-infra.json"
}
```

This file is append-only and committed to git. It provides an immutable audit trail for
compliance review.
