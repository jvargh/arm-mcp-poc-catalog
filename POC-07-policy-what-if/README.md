# Policy Compliance What-If Agent (ARM MCP PoC — POC-7)

A Copilot CLI / VS Code chat agent that simulates the impact of a **draft Azure Policy definition**
by translating its `if` block into Azure Resource Graph (ARG) queries and counting resources that
would be non-compliant if the policy were enforced — without deploying anything.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Accepts a draft Azure Policy JSON (the `if`/`then` block or a full definition) as input.
2. Parses the policy's `if` block and extracts all referenced field aliases.
3. Maps each alias to its ARG field path using the **fixed alias map** in `rules/rules.yaml`.
4. For each resolved alias: `validate_query` → `execute_query` (ARM MCP) to count would-be
   non-compliant resources.
5. Renders a report using a **fixed markdown template** (`templates/output-report.md`).
6. Optionally exports a full per-resource CSV to `exports/` for governance review.

## Why the output is deterministic

- Queries are NOT generated by the LLM at run time — they are read verbatim from `rules.yaml`
  with **only two string substitutions**: `{{alias_field}}` and `{{alias_value}}`.
- The alias map (policy alias → ARG field path) is fixed in `rules.yaml` and versioned.
- Sort orders, column headers, and section order are all pinned in `SKILL.md`.
- Run ID is `POL-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` — identical inputs → identical run ID.

## Determinism Deviation — KQL Templates

Per ratification #4, this PoC's KQL is **parameterized** with policy alias placeholders that get
substituted at runtime from the input policy JSON. This is still **literal KQL + string substitution**
— the substitution source is the policy JSON (not the runbook scope filter), and the KQL itself is
never authored or modified by the LLM.

The determinism contract holds: KQL is never authored by the LLM. The LLM performs exactly two
mechanical string substitutions per rule:

1. `{{alias_field}}` → the ARG property path (e.g., `tags.Owner`, `properties.hardwareProfile.vmSize`),
   resolved from the supported alias map in `rules.yaml`.
2. `{{alias_value}}` → the required value from the policy condition (e.g., `Standard_D2s_v3`),
   or the sentinel `__EXISTS__` when the policy condition is `exists: false`.

The substitution is deterministic for a given policy input: same policy JSON → same substitutions →
same KQL → same ARG results.

### Supported policy aliases

| Short Alias | Example Policy Field | ARG Field Path | Matched Rule |
|---|---|---|---|
| `sku` | `Microsoft.Compute/virtualMachines/sku.name` | `properties.hardwareProfile.vmSize` | R001 (compute) / R003 (storage: `sku.name`) |
| `location` | `location` | `location` | R002 (network) / R003 (storage) |
| `tags` | `tags['Owner']` | `tags.Owner` (tag name parsed from alias) | R001 (compute) / R003 (storage) / R004 (generic) |
| `networkAcls` | `Microsoft.Storage/storageAccounts/networkAcls.defaultAction` | `properties.networkAcls.defaultAction` | R002 (network/KeyVault) / R003 (storage) |

**Unsupported aliases** (any alias not in the above set): the agent emits a row
`STATUS=UNSUPPORTED ALIAS=<alias-name>` in the output report and continues — it does not fail or abort.

## How it works (end-to-end flow)

1. **Chat client routes the message.** VS Code Copilot Chat sees the `@policy-what-if` mention,
   loads `.github/copilot/agents/policy-what-if.agent.md` as the system prompt.
2. **Workspace MCP server starts.** Runtime reads `.vscode/mcp.json`, starts the ARM MCP server
   (`https://mcp.management.azure.com`), and enumerates tools.
3. **LLM follows SKILL.md step 1.** Reads `runbooks/prod.yaml` + `prod.values.yaml`, parses
   `policy_json` from the prompt.
4. **LLM resolves aliases (step 2).** For each `field` in the policy `if` block, looks up the
   short alias name and maps it to an ARG field path using `rules.yaml`.
5. **LLM computes `run_id` deterministically.** `POL-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.
6. **Per-alias loop (step 3).** For each resolved alias: substitutes `{{alias_field}}` and
   `{{alias_value}}` into the rule KQL, calls `validate_query`, then `execute_query`.
7. **Unsupported aliases.** Emitted as `STATUS=UNSUPPORTED ALIAS=<name>` rows; no query is run.
8. **Render (step 4).** Substitutes results into `templates/output-report.md`, optionally exports CSV.

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is **already declared** at workspace scope in `.vscode/mcp.json`.
   - If not yet authorized for the ARM MCP preview, visit <https://aka.ms/JoinARMMCP>.
   - For Copilot CLI: copy the `Azure Resource Manager MCP Server` entry from `.vscode/mcp.json`
     into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

## Configure your scope

Copy the example and fill in real values (this file is gitignored):

```powershell
Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
```

Edit `runbooks/prod.values.yaml`:

```yaml
subscription_id: "11111111-2222-3333-4444-555555555555"
policy_alias_map_version: "1"
output_format: "detailed"   # summary | detailed | csv

rg_include:
  - "payments-prod-rg"
  - "checkout-prod-rg"

rg_exclude: []
```

## Run

VS Code chat:

```
@policy-what-if simulate
```

Then paste or attach your draft policy JSON when prompted.

GitHub Copilot CLI:

```
gh copilot -p "Simulate policy impact for scope prod" --attach policy.json
```

Drill down on a specific resource:

```
@policy-what-if drilldown /subscriptions/.../resourceGroups/.../providers/.../vm-001
```

## Acceptance criteria mapping

| Criterion | Where it lives |
|---|---|
| Accepts policy JSON as input | `prompts/simulate.prompt.md` + `SKILL.md` step 1 |
| Maps common policy aliases to ARG fields | `rules/rules.yaml` (`alias_field_map`) + `SKILL.md` step 2 |
| Outputs summary chart data and per-resource list | `templates/output-report.md` (Summary + Would-Be Non-Compliant Resources sections) |
| Exports to CSV for governance review | `SKILL.md` step 4 (`output_format: csv` or `detailed`) |
