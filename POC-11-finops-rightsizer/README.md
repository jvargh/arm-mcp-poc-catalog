# FinOps Right-sizer (ARM MCP PoC — POC-11)

A Copilot CLI / VS Code chat agent that identifies idle and oversized Azure VMs via
Azure Resource Graph, generates ARM patch templates to resize them, shows a savings
estimate, and deploys on explicit confirmation.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed rule pack (`skills/finops-rightsizer/rules/rules.yaml`) — 4 weighted
   right-sizing checks with **pre-canned ARG queries**.
2. For every rule: `generate_query` → `execute_query` (ARM MCP).
3. Computes estimated monthly savings per candidate VM using the `savings_rate_per_sku`
   map from the runbook: `est_monthly_savings = savings_rate_per_sku[current_sku] - savings_rate_per_sku[target_sku]`.
4. Renders a report using a **fixed markdown template** (`templates/output-report.md`).
5. On `resize` verb with per-resource opt-in: calls `create_template_deployment` with
   `remediation/resize-vm.json` to patch `properties.hardwareProfile.vmSize`.
6. Writes a rendered report to `exports/rightsizer-<scope>-latest.md`.

## Why the output is deterministic

- Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
- The skill instructs the agent to emit the report using a fixed template with no paraphrasing.
- Savings formula is fixed: `(savings_rate_per_sku[current_sku] - savings_rate_per_sku[target_sku]) * count`.
- Sort orders, column headers, decimal precision, and section order are all pinned in `SKILL.md`.
- Run ID is deterministic: `RSIZE-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.
- Checklist format is fixed: `[ ] resource_name (current_sku → target_sku, est. $X/mo saved)`.

## Determinism Deviation

> **This PoC does not include `validate_query` in its tool allowlist per source spec
> (ratification #7 of `copilot-bishop-ratifications-2026-05-12.md`).**
>
> KQL correctness is assured by pre-testing during development. The `SKILL.md` procedure
> skips the `validate_query` step and goes directly to `generate_query` → `execute_query`.
>
> Operators running this PoC live should hand-verify `rules.yaml` KQL via the
> `validate_query` tool in another workspace if uncertain.

## How it works (end-to-end flow)

1. **Chat client routes the message.** VS Code Copilot Chat sees the `@finops-rightsizer`
   mention, loads `.github/copilot/agents/finops-rightsizer.agent.md` as the system prompt.
2. **Workspace MCP servers start.** The runtime reads `.vscode/mcp.json`, connects to
   `https://mcp.management.azure.com`.
3. **LLM follows skill step 1.** Reads `runbooks/prod.yaml` (scope, sub IDs, target SKUs,
   savings map, freeze flag) and `rules/rules.yaml`.
4. **LLM computes `run_id` deterministically.** `RSIZE-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.
5. **LLM enters the per-rule loop (skill step 2).** For each rule: takes the **literal** KQL
   from `rules.yaml`, calls `generate_query`, then `execute_query`.
6. **LLM computes savings per candidate (skill step 3).** Pure arithmetic from the
   `savings_rate_per_sku` map.
7. **LLM renders output (skill step 4).** Loads `templates/output-report.md` and does
   literal `{{placeholder}}` substitution.
8. **For `resize` verb:** LLM presents the opt-in checklist, runs the confirm gate
   (SKILL.md step 5 — checks `freeze_active`, awaits `YES`), then calls
   `create_template_deployment` per confirmed resource.

## Deploy safety model

This PoC is **DEPLOY-CAPABLE** but has strict guards:

| Guard | Behaviour |
|---|---|
| `freeze_active: true` in runbook | All deployments blocked unconditionally |
| `freeze_windows` match current UTC | Treated as `freeze_active: true` |
| Verb is not `resize` | `create_template_deployment` never called |
| No per-resource opt-in | Agent refuses to proceed |
| No explicit `YES` confirmation | Agent aborts after presenting summary |

> The agent's hard rules state: **"MUST NOT call `create_template_deployment` unless
> verb is `resize` AND user confirmed AND `freeze_active` is false."**

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is **already declared** at workspace scope in `.vscode/mcp.json`.
   - If your VS Code account isn't yet authorized for the ARM MCP preview, click through
     <https://aka.ms/JoinARMMCP> once.
   - For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server` entry
     from `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.
   For resize deploys you also need **Contributor** on the target RGs.

> The MCP server entry at workspace scope (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope (do this before first run)

`scope prod` maps to `runbooks/prod.yaml`. The agent loads that YAML to know which
subscriptions to query and which SKU pricing map to use for savings estimates.

### Two-file pattern: template + values

| File | Committed? | Contains |
|---|---|---|
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID, target SKUs, pricing map. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference — copy this to start. |

### First-time setup

1. **Copy the example to a real values file:**
   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```
2. **Edit `runbooks/prod.values.yaml`** and fill in real values (subscription ID, target SKU,
   savings rate map, freeze settings).
3. **Verify `.gitignore` excludes it** (root `.gitignore` has `**/runbooks/*.values.yaml`).

### Key runbook fields

| Field | Purpose |
|---|---|
| `target_environments` | Environment tag values to treat as right-size candidates |
| `target_sku` | Default resize target (rules may override) |
| `savings_rate_per_sku` | SKU → est. monthly USD cost map (operator-maintained) |
| `freeze_active` | Set `true` to block all deployments |
| `freeze_windows` | ISO-8601 intervals during which deployments are blocked |

## Agent verbs

| Verb | Mode | Deploys? |
|---|---|---|
| `scan` | Identify all candidates, show savings report | ❌ Read-only |
| `drilldown <resource>` | Deep-dive on one VM, show matching rules | ❌ Read-only |
| `resize` | Present checklist, gate, then patch VM sizes | ✅ Deploy (with gates) |

## Acceptance criteria mapping

| Criterion | Where it lives |
|---|---|
| ARG queries keyed on utilization tags / Advisor | `rules/rules.yaml` (R001–R004, R004 uses `advisorresources`) |
| ARM template patches `properties.hardwareProfile.vmSize` | `remediation/resize-vm.json` |
| Per-resource opt-in checklist before bulk deploy | `SKILL.md` Step 4 resize + Step 5 confirm gate; `prompts/resize.prompt.md` |
| Savings estimate per candidate | `SKILL.md` Step 3; `savings_rate_per_sku` map in runbook |
| Deterministic sort | desc by `est_monthly_savings`, ties by `resource_name` asc (pinned in SKILL.md + agent.md) |
| `freeze_active` respected | `SKILL.md` Step 5, `agent.md` hard rule #8 |
| What-if template only in tests | `exports/test-run.md` — scan output only; would-deploy appendix is NOT EXECUTED |
