# Post-Incident "What Changed" Reconstructor (ARM MCP PoC — SRE-PoC-11)

A Copilot CLI / VS Code chat agent that reconstructs the **full change timeline**
(ARM deployments, resource property changes, and RBAC changes) for a given incident
time window and scope — producing a **byte-near-identical postmortem artifact every time**
it is run with the same inputs.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed rule pack (`skills/post-incident-reconstructor/rules/rules.yaml`) —
   4 ARG queries with **pre-canned KQL** covering deployments, property changes, RBAC, and correlation.
2. For every rule: `validate_query` → `execute_query` (ARM MCP).
3. Merges rows from all rules into a single change timeline.
4. Sorts the timeline **ascending by timestamp** (earliest event first — narrative flow for postmortems).
5. Renders the timeline into a **fixed markdown template** (`templates/output-report.md`).
6. Supports `drilldown <deployment-id>` to focus on one deployment and its correlated changes.

## Why the output is deterministic

- Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
- The skill instructs the agent to emit the timeline using a fixed template with no paraphrasing.
- Sort order is pinned: ascending timestamp, ties by resource name ascending.
- Timeline entry format is pinned: `[HH:MM:SS UTC] <principal> <action> <resource> (deployment: <id>)`.
- Run ID is the input scope hash + UTC date — identical inputs → identical run ID.
- Numeric counts are integers; no decimals.

## How it works (end-to-end flow)

1. **Chat client routes the message.** VS Code Copilot Chat sees the `@post-incident-reconstructor`
   mention, loads [`.github/copilot/agents/post-incident-reconstructor.agent.md`](.github/copilot/agents/post-incident-reconstructor.agent.md)
   as the system prompt, and reads its `tools:` / `mcp:` declarations.
2. **Workspace MCP servers start.** The runtime reads [`.vscode/mcp.json`](.vscode/mcp.json), sees the
   `Azure Resource Manager MCP Server` entry and performs the MCP `initialize` handshake.
3. **LLM loads configuration.** Reads `runbooks/prod.yaml` + `prod.values.yaml` to extract
   `incident_time_window`, `incident_scope`, and `subscriptions`. Reads `rules.yaml` and computes
   `ruleset_hash8` via SHA-256.
4. **LLM computes `run_id`** deterministically: `POST-{YYYYMMDD}-{scope}-{ruleset_hash8}`.
5. **LLM enters the per-rule loop.** For each rule it takes the **literal** KQL from `rules.yaml`,
   substitutes `${start_utc}`, `${end_utc}`, and scope tokens, then calls `validate_query`.
6. **`validate_query` round-trip** to `https://mcp.management.azure.com`.
7. **Conditional branch on validate result.**
   - Valid → call `execute_query` with the same KQL.
   - Invalid → mark rule `INVALID`, continue.
8. **Skippable-table handling (R002, R003).** If `execute_query` returns empty or table-not-found,
   emit `STATUS=SKIPPED REASON=<table>-unavailable` inline and continue. Never abort.
9. **Deployment enrichment.** For each deployment ID in R001 results, calls
   `get_arm_template_deployment_status` to retrieve final `provisioningState`.
10. **Timeline merge and sort.** Rows from R001 + R002 + R003 + R004 merged; sorted ascending
    by timestamp; ties by resource name ascending.
11. **Render output.** Loads `templates/output-report.md` and substitutes placeholders literally.
    Streams the rendered report to chat.

## Install

1. Clone this folder anywhere and open it as a workspace in VS Code.
   The ARM MCP server is **already declared** at workspace scope in [`.vscode/mcp.json`](.vscode/mcp.json).
   - If your VS Code account isn't yet authorized for the ARM MCP preview, click through
     <https://aka.ms/JoinARMMCP> once.
   - For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server` entry from
     `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

> The MCP server entry at workspace scope (`.vscode/mcp.json`):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope (do this before first run)

`scope prod` maps to [`runbooks/prod.yaml`](runbooks/prod.yaml). The agent loads that YAML to
know **which subscriptions**, **which time window**, and **which resource groups** to query.

### Two-file pattern: template + values

| File | Committed? | Contains |
|---|---|---|
| [`runbooks/prod.yaml`](runbooks/prod.yaml) | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID, incident window, RG names. |
| [`runbooks/prod.values.yaml.example`](runbooks/prod.values.yaml.example) | ✅ yes | Schema reference — copy this to start. |

### First-time setup

1. **Copy the example:**
   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```

2. **Edit `runbooks/prod.values.yaml`** and fill in real values:
   ```yaml
   subscription_id: "463a82d4-1896-4332-aeeb-618ee5a5aa93"
   incident_start_utc: "2026-05-10T14:00:00Z"
   incident_end_utc:   "2026-05-10T15:30:00Z"
   incident_scope: "resourceGroup"
   rg_include:
     - "payments-prod-rg"
   rg_exclude: []
   postmortem_template_format: "standard"
   ```

3. **Verify `.gitignore`** excludes it (root `.gitignore` has `**/runbooks/*.values.yaml`).

## Run

VS Code chat:

```
@post-incident-reconstructor reconstruct for scope prod
```

GitHub Copilot CLI:

```
gh copilot -p "Reconstruct the post-incident change timeline for scope prod"
```

Drill-down on one deployment:

```
@post-incident-reconstructor drilldown deploy-payments-api-20260510-1403
```

## Acceptance criteria mapping

| Criterion | Where it lives |
|---|---|
| Time- and scope-bounded ARG over resourcechanges + authorizationresources | `rules/rules.yaml` R002 + R003 |
| Correlates to ARM deployment IDs | `rules/rules.yaml` R001 + R004 |
| Output formatted for postmortem template | `templates/output-report.md` + `SKILL.md` |
| SKIPPED state for unavailable tables (R002, R003) | `rules.yaml` `skip_if_unavailable: true` + SKILL.md step 2.5 |
| Timeline ascending by timestamp, ties by resource name | SKILL.md step 4.3 + agent.md hard rule 5 |
| Canonical entry format pinned | agent.md hard rule 6 + SKILL.md output contract |

## Special concerns — ratification notes

Per ratifications #1 and #2 from `copilot-bishop-ratifications-2026-05-12.md`:

- **R002 (`resourcechanges`)** is marked `skip_if_unavailable: true`. The `resourcechanges`
  table requires Change History to be enabled in the subscription. If it is not enabled,
  `execute_query` returns empty or a table-not-found error. The skill emits
  `STATUS=SKIPPED REASON=resourcechanges-unavailable` inline and continues with R001/R003/R004.
- **R003 (`authorizationresources`)** is similarly marked `skip_if_unavailable: true`.
  If unavailable, the skill emits `STATUS=SKIPPED REASON=authorizationresources-unavailable`
  and continues.

To enable `resourcechanges` in your subscription:
```powershell
az policy assignment create --policy "06a78e20-9358-41c9-923c-fb736d382a4d" \
  --name "enable-change-history" --scope "/subscriptions/<sub-id>"
```
