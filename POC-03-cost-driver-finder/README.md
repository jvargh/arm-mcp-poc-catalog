# "Where did my money go?" Cost-Driver Finder (ARM MCP PoC)

A Copilot CLI / VS Code chat agent that surfaces **likely cost drivers** (resources that were  
recently created, recently modified, or are missing owner tags) in an Azure scope, by querying  
Azure Resource Graph (ARG). It emits a **byte-near-identical report every time** it is run with  
the same scope and ruleset.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What this is (and is NOT)

**ARG has no access to billing or cost data.** This tool does not read USD spend, does not  
compute savings, and does not rank resources by actual cost. It answers a different question:

> "Which resources in my scope are the most likely _suspects_ for a recent cost change,  
> based on what's new, what changed, and what's untagged?"

| ✅ This tool DOES | ❌ This tool does NOT |
| --- | --- |
| List resources **created** in the last N days (R001) | Show how much any resource costs in USD |
| List resources **modified** in the last N days (R002) | Identify cost savings or rightsizing opportunities |
| List resources **missing owner tags** in a region (R003) | Replace Azure Cost Management / Cost Analysis |
| Produce a deterministic shortlist of investigation targets | Detect SKU upgrades, scale events, or pricing changes |
| Hand off that shortlist to Cost Management for USD lookup | Tell you _why_ the bill went up |

Use this as the **first triage step** when a bill spikes: it narrows hundreds of resources down  
to a deterministic shortlist of "what changed recently and who owns it." Then take that  
shortlist into Azure Cost Management (or the `azure-cost` skill) to attach real dollar figures.

## What it does

1.  Loads a fixed rule pack (`skills/cost-driver-finder/rules/rules.yaml`) - 3 cost-driver  
    rules with **pre-canned ARG queries**.
2.  For every rule: `generate_query` → `execute_query` (ARM MCP). (`validate_query` is excluded  
    from the tool allowlist - see [Determinism Deviation](#determinism-deviation) below.)
3.  Surfaces new resources (R001), recently modified resources (R002), and untagged resources  
    in the target region (R003).
4.  Renders a report using a **fixed markdown template** (`templates/output-report.md`).
5.  Optionally emits a handoff note to Azure Cost Management. The tool itself reports **no**  
    **USD figures**; Cost Management is where actual spend lookup happens.

## Why the output is deterministic

*   Queries are NOT generated by the LLM at run time - they are read verbatim from YAML.
*   The skill instructs the agent to emit the report using a fixed template with no paraphrasing.
*   Sort orders, column headers, and section order are all pinned in `SKILL.md`.
*   Run ID is `COST-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}` - identical inputs → identical run ID.
*   Time window and region are substituted from the values file, not entered by the user at runtime.

## How it works (end-to-end flow)

What happens after you type `@cost-driver-finder run for scope prod`:

1.  **Chat client routes the message.** VS Code Copilot Chat sees the `@cost-driver-finder`  
    mention, loads `.github/copilot/agents/cost-driver-finder.agent.md` as the system prompt.
2.  **Workspace MCP server starts.** The runtime reads `.vscode/mcp.json`, initializes the  
    ARM MCP server at `https://mcp.management.azure.com`, and exposes `generate_query` and  
    `execute_query` to the agent.
3.  **LLM follows skill step 1 - load inputs.** It reads `runbooks/prod.yaml` + values file,  
    extracts `subscriptions`, `time_window_days`, `target_region`, `rg_include`, `rg_exclude`.
4.  **LLM computes** `**run_id**` **deterministically.**  
    `COST-{YYYYMMDD}-prod-{sha256(rules.yaml)[:8]}` - plain string assembly.
5.  **LLM enters the per-rule loop (skill step 2).** For each rule it takes the **literal** KQL  
    from `rules.yaml`, substitutes `${time_window_days}` and `${target_region}` from the runbook,  
    and calls `generate_query` with that string.
6.  `**generate_query**` **→** `**execute_query**`**.** No `validate_query` call (see Determinism Deviation).
7.  **LLM applies rg\_include/rg\_exclude filters** to returned rows.
8.  **LLM renders via** `**templates/output-report.md**` - literal placeholder substitution.
9.  **Report streamed back to chat.**

## Determinism Deviation

This PoC does not include `validate_query` in its tool allowlist per source spec. KQL  
correctness is assured by pre-testing during development. Operators running this PoC live  
should hand-verify rules.yaml KQL via the `validate_query` tool in another workspace if  
uncertain.

The call sequence for this PoC is: `generate_query` → `execute_query` (skipping `validate_query`).  
This deviates from the standard fleet pattern (`validate_query` → `execute_query`) and is  
recorded here per the Determinism Contract §2 and Ratification #7 (2026-05-12).

## Install

1.  Clone this folder anywhere and open it as a workspace in VS Code.  
    The ARM MCP server is **already declared** at workspace scope in `.vscode/mcp.json` -  
    VS Code will prompt you to start it the first time you open the chat.
    *   If your VS Code account isn't yet authorized for the ARM MCP preview, click through  
        \<https://aka.ms/JoinARMMCP\> once.
    *   For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server` entry from  
        `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2.  Sign in to Azure (`az login`) with Reader + Resource Graph Reader on the target scope.

## Configure your scope (do this before first run)

`scope prod` maps to `runbooks/prod.yaml`. Two-file pattern keeps secrets out of git:

| File | Committed? | Contains |
| --- | --- | --- |
| `runbooks/prod.yaml` | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID, region, time window. |
| `runbooks/prod.values.yaml.example` | ✅ yes | Schema reference - copy this to start. |

### Runbook keys

| Key | Required | Default | Purpose |
| --- | --- | --- | --- |
| `subscription_id` | yes | \- | Azure subscription to query |
| `rg_include` | no | all | RG name substrings to include |
| `rg_exclude` | no | none | RG name substrings to exclude |
| `time_window_days` | yes | 30 | Look-back window in days |
| `target_region` | yes | \- | Azure region to filter (e.g. `eastus2`) |
| `cost_threshold_usd` | no | null | Optional future Cost Management handoff |

## Run

VS Code chat:

```
@cost-driver-finder run for scope prod
```

GitHub Copilot CLI:

```
copilot -p "Run cost-driver-finder for scope prod"
```

> **CLI users:** see [Copilot CLI usage notes](../README.md#copilot-cli-usage-notes) — `gh copilot` has a quoting bug on Windows when `copilot` lives on a path with spaces, `@agent` mentions don't work in the CLI, and first runs take a few minutes.

Drill-down on one resource group:

```
@cost-driver-finder drilldown payments-prod-rg
```

## Notes on `resourcechanges` table (R002)

The `resourcechanges` table is not available in all subscription tenants. R002 is marked  
`skip_if_unavailable: true` in `rules.yaml`. If the table is unavailable, the agent emits:

```
STATUS=SKIPPED REASON=resourcechanges-unavailable
```

and continues with R003. Live validation will determine whether the table is enabled in your  
subscription. See Ratification #1 (2026-05-12).
