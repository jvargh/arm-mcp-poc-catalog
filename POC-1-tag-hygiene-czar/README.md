# Tag Hygiene Czar (ARM MCP PoC — POC-1)

A Copilot CLI / VS Code chat agent that finds Azure resources non-compliant with
tag policy and generates/deploys ARM patches to fix them.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed tag-compliance rule pack (`skills/tag-hygiene-czar/rules/rules.yaml`) —
   4 weighted tag checks (R001–R004) with **pre-canned ARG queries**.
2. For every rule: `validate_query` → `execute_query` (ARM MCP).
3. Groups findings by resource group, resource type, and resource name.
4. Renders a report using a **fixed markdown template** (`templates/output-report.md`).
5. On the `apply` verb (with explicit confirmation): deploys ARM patches via
   `Microsoft.Resources/tags` to apply missing tags to non-compliant resources.

## Why the output is deterministic

- Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
- The skill instructs the agent to emit the report using a fixed template with no paraphrasing.
- Sort order is fixed: resource group ascending → resource type ascending → resource name ascending.
- Tag compliance is **binary per resource per tag** — a resource either has the tag
  (non-empty value) or it does not. No partial credit.
- Run ID is the input scope hash + UTC date — identical inputs → identical run ID.
- Numeric output is integer unless source data is a percentage (1 decimal place).

## How it works (end-to-end flow)

After you type `@tag-hygiene-czar scan for scope prod`:

1. VS Code Copilot Chat loads `.github/copilot/agents/tag-hygiene-czar.agent.md` as
   the system prompt and reads its `tools:` / `mcp:` declarations.
2. The runtime reads `.vscode/mcp.json`, starts the ARM MCP server, and lists available tools.
3. The LLM reads `runbooks/prod.yaml` (substituting from `prod.values.yaml`) and
   `rules/rules.yaml`, then computes `run_id = TAG-{YYYYMMDD}-{scope}-{ruleset_hash8}`.
4. For each rule (R001–R004), the LLM calls `validate_query` → `execute_query` with the
   literal KQL from `rules.yaml` and the subscriptions from the runbook.
5. Results are filtered by `rg_include` / `rg_exclude`, then sorted and rendered into
   `templates/output-report.md` by literal `{{placeholder}}` substitution.
6. The rendered report is written to `exports/tag-report-prod-latest.md` and streamed
   back to chat. No further MCP calls.

For the `apply` verb, the flow adds a mandatory **confirm gate** (see SKILL.md Step 5)
before any `create_template_deployment` call.

## Acceptance criteria

| Criterion | Where it lives |
|---|---|
| Configurable required-tag set via YAML | `runbooks/prod.values.yaml` → `required_tags` list |
| CSV/markdown report grouped by RG and resource type | `templates/output-report.md` + `exports/tag-report-<scope>-latest.md` |
| ARM template applies missing tags via `Microsoft.Resources/tags` | `remediation/apply-missing-tags.json` |
| Dry-run (scan) mode | `verb = scan` — read-only, zero deploys |
| Apply mode with confirmation gate | `verb = apply` + SKILL.md Step 5 confirm gate |

## Determinism notes

- **Sort:** resource group (ascending) → resource type (ascending) → resource name (ascending).
- **Tag compliance:** binary per resource per tag (present + non-empty = compliant).
- **Run ID prefix:** `TAG`.
- **run_id format:** `TAG-{YYYYMMDD}-{scope}-{sha256(rules.yaml)[:8]}`.

## Deploy safety

This PoC is `DEPLOY`-capable. The following hard rules govern deployment:

- `scan` and `drilldown` verbs are **strictly read-only** — they call only
  `validate_query` and `execute_query`. No `create_template_deployment`.
- `apply` verb requires:
  1. `freeze_active: false` in the runbook.
  2. An explicit confirm gate (user must reply `yes, apply tags`).
  3. Only then is `create_template_deployment` called (mode `Incremental`).
- `freeze_active: true` in the runbook aborts the apply flow before any deploy.

See `agents/tag-hygiene-czar.agent.md` hard rule #7 and SKILL.md Step 5 for details.

## Install

1. Clone this folder and open it as a workspace in VS Code.
   The ARM MCP server is already declared at workspace scope in `.vscode/mcp.json`.
   - If your VS Code account isn't yet authorized for the ARM MCP preview, click through
     <https://aka.ms/JoinARMMCP> once.
   - For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server` entry
     from `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with **Reader** + **Resource Graph Reader** on the
   target scope. For the `apply` verb you also need **Tag Contributor** (or **Contributor**)
   on the target resource groups.

> MCP server entry (workspace scope):
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope (do this before first run)

`scope prod` maps to [`runbooks/prod.yaml`](runbooks/prod.yaml). A two-file pattern keeps
secrets out of git:

| File | Committed? | Contains |
|---|---|---|
| [`runbooks/prod.yaml`](runbooks/prod.yaml) | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID, RG names, tag defaults. |
| [`runbooks/prod.values.yaml.example`](runbooks/prod.values.yaml.example) | ✅ yes | Schema reference — copy this to start. |

### First-time setup

1. Copy the example:
   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```
2. Edit `runbooks/prod.values.yaml` with your real values:
   ```yaml
   subscription_id: "11111111-2222-3333-4444-555555555555"
   rg_include:
     - "payments-prod-rg"
     - "checkout-prod-rg"
   rg_exclude: []
   required_tags:
     - CostCenter
     - DataClassification
     - Owner
     - Environment
   default_tag_values:
     CostCenter: "UNKNOWN"
     DataClassification: "Internal"
     Owner: "platform-team@example.com"
     Environment: "prod"
   ```
3. Verify `.gitignore` excludes it (root `.gitignore` has `**/runbooks/*.values.yaml`).

### Runbook keys

| Key | Type | Purpose |
|---|---|---|
| `subscription_id` | string | Azure subscription GUID to query |
| `rg_include` | list | Allow-list of RG name substrings (case-insensitive) |
| `rg_exclude` | list | Block-list of RG name substrings (case-insensitive) |
| `required_tags` | list | Tag keys to enforce; drives which rules are active |
| `default_tag_values` | map | Tag values applied during `apply` verb |
| `freeze_active` | boolean | Set `true` to block all `apply` deployments |
| `freeze_windows` | list | Informational freeze time windows |
