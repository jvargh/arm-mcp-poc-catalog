# Crown Jewels Security Posture (ARM MCP PoC — POC-10)

A Copilot CLI / VS Code chat agent that surfaces the **highest-blast-radius** Azure
resources in a scope — public-facing, holding identities/keys, or burdened with broad
RBAC assignments — via multi-join ARG queries with severity scoring.

Backed by the [Azure Resource Manager MCP Server](https://aka.ms/JoinARMMCP).

## What it does

1. Loads a fixed rule pack (`skills/crown-jewels-security/rules/rules.yaml`) — 5 weighted
   security checks with **pre-canned ARG queries**.
2. For every rule: `validate_query` → `execute_query` (ARM MCP).
3. Computes a **severity score** per resource: `severity = sum(weight × category_multiplier)`
   for each rule the resource matches.
4. Renders a report using a **fixed markdown template** (`templates/output-report.md`),
   sorting resources descending by severity score (ties broken by resource name ascending).
5. Writes a SARIF 2.1.0 or CSV export to `exports/` for SecOps intake.

## Why the output is deterministic

* Queries are NOT generated by the LLM at run time — they are read verbatim from YAML.
* The skill instructs the agent to emit the report using a fixed template with no paraphrasing.
* Scoring formula is fixed: `severity = sum(weight × severity_weights[category])`.
* Sort orders, column headers, decimal precision, and section order are all pinned in `SKILL.md`.
* Run ID is the input scope name + UTC date + rules.yaml hash — identical inputs → identical run ID.

## How it works (end-to-end flow)

What happens after you type `@crown-jewels-security scan for scope prod`:

1. **Chat client routes the message.** VS Code Copilot Chat sees the
   `@crown-jewels-security` mention, loads
   [`.github/copilot/agents/crown-jewels-security.agent.md`](.github/copilot/agents/crown-jewels-security.agent.md)
   as the system prompt, and reads its `tools:` declarations.
2. **Workspace MCP servers start.** The runtime reads [`.vscode/mcp.json`](.vscode/mcp.json),
   starts the `Azure Resource Manager MCP Server`, and fetches the tool list.
3. **LLM follows SKILL.md step 1 — load inputs.** It reads `runbooks/prod.yaml` (scope,
   sub IDs, RG list, severity weights, export format) and `rules/rules.yaml`.
4. **LLM computes `run_id` deterministically.** `SEC-{YYYYMMDD}-prod-{sha256(rules.yaml)[:8]}`.
5. **LLM enters the per-rule loop (SKILL.md step 2).** For each rule it takes the
   **literal** KQL from `rules.yaml`, injects the scope filter, then calls
   `validate_query` → `execute_query`.
6. **authorizationresources fallback.** For rules R002 and R005 (flagged
   `skip_if_unavailable: true`), if `execute_query` returns empty or errors with
   table-not-found, the agent emits
   `STATUS=SKIPPED REASON=authorizationresources-unavailable` and continues.
7. **LLM scores every matched resource (SKILL.md step 3).**
   `severity_score = sum(weight × severity_weights[category])` per resource.
8. **LLM renders the output (SKILL.md step 4).** Fills
   [`templates/output-report.md`](.github/copilot/skills/crown-jewels-security/templates/output-report.md)
   with literal placeholder substitution.
9. **LLM writes the SARIF/CSV export** to `exports/`.
10. **LLM streams the result back to chat.**

## Install

1. Clone this folder anywhere and open it as a workspace in VS Code.  
   The ARM MCP server is **already declared** at workspace scope in
   [`.vscode/mcp.json`](.vscode/mcp.json).
   * If your VS Code account isn't yet authorized for the ARM MCP preview, click through
     <https://aka.ms/JoinARMMCP> once.
   * For GitHub Copilot CLI users: copy the `Azure Resource Manager MCP Server` entry
     from `.vscode/mcp.json` into `~/.copilot/mcp.json`.
2. Sign in to Azure (`az login`) with **Reader** + **Resource Graph Reader** on the target scope.

> MCP server entry (workspace-scoped):
>
> ```json
> {
>   "servers": {
>     "Azure Resource Manager MCP Server": {
>       "type": "http",
>       "url": "https://mcp.management.azure.com"
>     }
>   }
> }
> ```

## Configure your scope (do this before first run)

`scope prod` maps to [`runbooks/prod.yaml`](runbooks/prod.yaml).
Scope configuration uses the same two-file pattern as the reference implementation:

| File | Committed? | Contains |
| --- | --- | --- |
| [`runbooks/prod.yaml`](runbooks/prod.yaml) | ✅ yes | Template with `${placeholder}` tokens. No real values. |
| `runbooks/prod.values.yaml` | ❌ **gitignored** | Your real subscription ID(s) and RG names. |
| [`runbooks/prod.values.yaml.example`](runbooks/prod.values.yaml.example) | ✅ yes | Schema reference — copy this to start. |

### First-time setup

1. Copy the example:
   ```powershell
   Copy-Item runbooks/prod.values.yaml.example runbooks/prod.values.yaml
   ```
2. Edit `runbooks/prod.values.yaml` with real values:
   ```yaml
   subscription_id: "11111111-2222-3333-4444-555555555555"
   rg_include:
     - "payments-prod-rg"
   rg_exclude: []
   crown_jewel_tags:
     - "Criticality=High"
   ```
3. Verify `.gitignore` excludes it (root `.gitignore` has `**/runbooks/*.values.yaml`).

### Runbook keys

| Key | Purpose | Default |
| --- | --- | --- |
| `subscriptions` | Sub IDs to query | all accessible subs |
| `workload_key` | Grouping field (`resourceGroup` or a tag name) | `resourceGroup` |
| `rg_include` | Allow-list of RG substrings | all RGs |
| `rg_exclude` | Block-list of RG substrings | none |
| `severity_weights` | Per-category weight multiplier map | all 1.0 |
| `export_format` | `sarif` or `csv` | `sarif` |
| `crown_jewel_tags` | Optional tag filter for eligible resources | none |

VS Code chat:

@crown-jewels-security scan for scope prod

## Acceptance criteria mapping

| Criterion | Where it lives |
| --- | --- |
| Joins resources + role assignments + network exposure facets | `rules.yaml` R001 (resources join), R002/R005 (authorizationresources), R003/R004 (resources) |

## Defensive fallbacks

### `authorizationresources` table unavailability (R002, R005)

Rules R002 and R005 query the `authorizationresources` ARG table, which requires
elevated Resource Graph permissions and may not be enabled for all subscriptions.

**Behavior when unavailable:**

If `execute_query` returns an empty result set OR returns any error mentioning
`authorizationresources` (table not found, insufficient permission), the agent:

1. Emits one output row: `STATUS=SKIPPED REASON=authorizationresources-unavailable`
2. Records the rule as `SKIPPED` in the Summary table.
3. Continues with the remaining rules — **the scan does not abort**.

Both R002 and R005 are marked `skip_if_unavailable: true` in `rules.yaml` so the
skill can identify them without string-matching the table name.

**To enable these rules in your subscription:**

Ensure your identity has the `Resource Graph Reader` role at subscription scope, and that
the subscription's Resource Graph configuration includes the `authorizationresources`
table (see [ARG table availability](https://learn.microsoft.com/azure/governance/resource-graph/reference/supported-tables-resources)).

### `validate_query` failures

If `validate_query` returns a syntax or auth error for any rule, the rule is marked
`INVALID`, the error message is stored, and the scan continues. Failed validations are
reported in the `## Skipped / Invalid Rules` section of the rendered report.
